# Проверка графа и темпа РТ

Приём взят из скилла `level-design` (gamedev-skills/awesome-gamedev-agent-skills, Apache-2.0) и переложен на РТ.

## 1. Граф (JSON рядом с концептом)
```json
{
  "start": ["шлюз А", "шлюз Б"],
  "goal": "хранилище",
  "exits": ["грузовой ствол", "вентшахта"],
  "hot": "хранилище",
  "rooms": {
    "шлюз А":   { "exits": [ { "to": "казармы" } ] },
    "казармы":  { "exits": [ { "to": "шлюз А" }, { "to": "дизельная" } ], "grants": "карта доступа" },
    "дизельная": { "exits": [ { "to": "казармы" }, { "to": "хранилище", "needs": "ток" } ], "grants": "ток" },
    "хранилище": { "exits": [ { "to": "дизельная" }, { "to": "грузовой ствол", "needs": "карта доступа" } ] }
  },
  "beats": [ { "room": "шлюз А", "type": "teach", "i": 0.1 }, { "room": "казармы", "type": "combat", "i": 0.5 } ]
}
```
- Выход из комнаты — **односторонний**: дверь пиши в обе стороны, прыжок/провал — в одну.
- `grants` — что даёт комната (карта, перфокарта, ток, рычаг); `needs` — что нужно для прохода. Ключи не тратятся;
  расходуемое — отдельной пометкой `"consume": true` (проверка тогда строже — считай вручную).

## 2. Что проверяет `scripts/rt-check.py граф.json`
1. Цель достижима из **каждого** старта с ключами, которые реально можно получить по пути (поиск по состояниям
   «комната + набор ключей»). Простой flood-fill не годится: он пропустит ключ за своей дверью.
2. Из цели достижим хотя бы один выход; из каждой точки после одностороннего прыжка — выход (иначе ловушка).
3. У горячей зоны ≥ 3 входящих направления и ≥ 2 исходящих.
4. Темп: не больше двух «высоких» битов (≥ 0,7) подряд; перед кульминацией (`climax`) — отдых (`rest`);
   первый бит — знакомство (`teach`) или отдых.
Код возврата 0 — всё годно; иначе печатает список проблем.

## 3. После проверки
Проблемы — чинить граф, а не картинку. Дальше: макет, скрин-прогоны, `--simtest` с ботами, вопросы пользователю
для плейтеста («где не понял, куда идти; где умер и почему; сколько длился заход»).
