# Раствордд — правила для агентов (Claude, GPT/Codex и др.)

Это отдельный проект. К Enter the Gungeon и его моду отношения не имеет.

## Кто перед тобой: владелец или напарник
Над проектом работают двое, у каждого свой Claude. Проверь `git config user.name`:
- **LedokoI** — владелец. Отвечать коротко, по делу, без лишних объяснений.
- **кто угодно другой** — напарник. Он новичок в git и в этом проекте. Твоя роль — наставник и помощник во всём:
  - Весь git делай за него сам и объясняй простыми словами, что произошло: забрать обновления (`git pull --rebase --autostash`), закоммитить, отправить (`git push` — разрешено), разрешить конфликт. Никогда не делай `push --force`, `reset --hard`, удаление веток без его явного «да».
  - В начале сессии сам забери обновления и коротко расскажи, что изменилось у владельца (`git log` с прошлого раза).
  - Объясняй, где что лежит и как устроено (`HANDOFF.md`, `docs/`), предлагай следующий шаг, не бросай его с ошибкой — разбирай её вместе с ним.
  - Перед правкой «общих» файлов (`game/src/Client/Main.cs`, `Hud.cs`, `game/src/Sim/World.cs`) предупреди: их часто правит владелец — лучше отправлять маленькими кусками и почаще.
  - Его идеи записывай в `docs/ideas-log.md` с пометкой «(напарник)», чтобы владелец их видел.
- Если git-имя не настроено — спроси, как его зовут, и настрой `git config user.name/user.email` для этого репозитория.

## Перед любой работой
1. Прочитай `docs/00-vision.md` (суть игры и опоры) и `docs/decisions.md` (что уже решено).
2. Для задачи по конкретной системе прочитай её блок в `docs/design/`.
3. Не противоречь принятым решениям молча. Если хочешь предложить иное, допиши в `docs/decisions.md` → «Открытые вопросы».

## Журнал идей (обязательно)
- Каждую новую идею, хотелку или правку от пользователя переформулируй коротко и допиши в `docs/ideas-log.md` с датой (новые записи снизу).
- Если идея влияет на дизайн, обнови соответствующий файл в `docs/design/` и/или `docs/decisions.md`.
- Ничего из сказанного пользователем не теряй: лучше записать лишнее.

## Правила работы
- Субагентов запускать только с reasoning effort `medium` или `low`.
- Язык документации: русский.
- Код игры: C# (Godot 4 .NET), см. `docs/design/09-tech.md`.
- Логику симуляции держать отдельно от отображения (сервер-авторитарная архитектура, даже в одиночной игре).
- Творческие задачи можно отдавать Codex («Астра», приложение OpenAI Codex уже залогинено): `scripts/gen-assets.ps1` (картинки), `scripts/gpt-tasks.ps1` (тексты). Усилие Codex — не выше `medium` (`-c model_reasoning_effort="medium"`).

## Как собирать, запускать и проверять
- Сборка: `dotnet build game -v q -nologo` (из корня репозитория).
- Движок: `tools/godot/Godot_v4.7.2-stable_mono_win64/` — `…_win64.exe` для игры, `…_console.exe` для прогонов и скриншотов. Новые картинки — сначала `--headless --path game --import`.
- Игра: `Играть.cmd`; песочница ботов: `Наблюдать за ботами.cmd` (`--spectate`: Tab — следить за ботом, F — свободная камера, 1–4 — скорость).
- Пользователь разрешает запускать игру и гонять её для проверок.
- Скриншот-прогон: `…_console.exe --path game -- --frames=N --shot=путь.png --do=кадр:действие,…` (действия: give<id>x<n>, slotN, at<dx>;<dy>, fire, interact, ui<op>_<арг>, craftmenu, tech, learn<id>, piece<n>, bmenu, peace, info, pathtest…; места: --buildspot, --atcrate, --spawn=x,y, --aim=x,y).
- Прогон ботов: `--simtest=секунды[,бот,home|base]` (+ `--frames=3 --shot=…`, чтобы процесс завершился), лог — строки «ВЕХА» и «МЫСЛЬ»; `--raidkit=секунда` — первый бот получает бомбы. Разбор зависаний: `python scripts/bot-stalls.py лог.log`.
- **Сохранение игрока** (`%APPDATA%\Godot\app_userdata\Rastvordd\world_save.json`) читается и пишется ТОЛЬКО при обычном запуске без аргументов. Любой отладочный запуск — свежий мир. Не ломать это правило: однажды тест чуть не перезаписал мир пользователя.
- Перед тем как открыть вторую копию игры, закрыть первую (`CloseMainWindow`), иначе обе пишут одно сохранение.
