# Процедурная сборка РТ

По скиллу `procedural-gen` (gamedev-skills, Apache-2.0) + решения О42 (docs/design/20-object42.md).

## Принципы
1. **Свой генератор случайности**: один сид → один макет. Отдельные потоки на макет, лут, охрану, обстановку
   (`random.Random(seed)`, дочерние — `Random(rng.getrandbits(64))`), чтобы новая бочка не перетряхнула стены.
2. **Выучиваемость**: геометрия — раз в вайп (сид вайпа), между заходами меняются наполнение, охрана, какие выходы открыты.
3. **Порядок**: вертикальный скелет (шахты, лестницы, атриумы — соосные) → ориентиры (крупные залы, главный крейт) →
   районы и петли комнат (3–6 комнат в петле, 2–3 выхода у обычной комнаты, тупиков ≤ 10 %) → двери и ключи →
   лут и охрана → обстановка.
4. **Данные отдельно от картинки**: генератор пишет JSON (как `Tier*Layouts.g.cs`), C# только читает.
5. **Проверка каждого результата**: граф комнат из макета → `scripts/rt-check.py` (цель достижима, выходы, ≥ 3 входа
   в горячую зону, нет ловушек), прострел внутри ≤ 18 м, у старта нет прямой линии на другой старт.
   Провал → новый сид из производного (`seed*1000+n`) или починка.
6. **Прогон по сидам**: 200 сидов — доля провалов, средняя длина пути старт→цель, разброс числа комнат.
   Печатать цифры и класть превью (`assets/…png`) для пользователя.

## Приёмы
- **Модули** (комнаты-шаблоны с портами дверей) + граф районов — основной путь для О42 и хрущёвки.
- **BSP / размещение + остовное дерево + 15 % лишних рёбер** — для петель.
- **WFC** (mxgmn/WaveFunctionCollapse, DeBroglie для C#, godot-constraint-solving) — для обстановки и «мусорных» зон,
  не для критического пути: цель и ключи ставятся руками/правилами.
- Числа и веса — в одной таблице (как `Sim/Data/Progression.cs`), чтобы пользователь мог менять без кода.
